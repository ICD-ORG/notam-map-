## התקנה — 6 שלבים (כ-20 דקות, פעם אחת בלבד)

### שלב 1 — חשבון GitHub
נכנסים ל-github.com → **Sign up** → נרשמים עם אימייל של הארגון. (אם כבר יש חשבון — מדלגים.)

### שלב 2 — יצירת מאגר (Repository)
לוחצים על **+** בפינה הימנית העליונה → **New repository**:
- **Repository name**: `notam-map`
- בוחרים **Public** (חובה — כדי ש-GitHub Pages יעבוד בחינם)
- מסמנים ✅ **Add a README file**
- לוחצים **Create repository**

### שלב 3 — העלאת הקבצים
בתוך המאגר: **Add file → Upload files** → גוררים לחלון את **כל** תוכן ה-ZIP:
`index.html` , `notam-data.json` , `updater.py` **וגם את התיקייה** `.github` (גוררים את התיקייה כולה — הדפדפן יודע להעלות תיקיות).
למטה לוחצים **Commit changes**.

> אם התיקייה `.github` לא עולה בגרירה: לוחצים **Add file → Create new file**, בשם הקובץ מקלידים בדיוק `.github/workflows/update.yml` (הלוכסנים יוצרים את התיקיות), מדביקים את תוכן הקובץ, ו-**Commit**.

### שלב 4 — הפעלת האתר (GitHub Pages)
במאגר: **Settings → Pages** (בתפריט הצד):
- תחת **Source** בוחרים: **Deploy from a branch**
- **Branch**: `main` , תיקייה `/ (root)` → **Save**
- אחרי 1–2 דקות תופיע למעלה הכתובת: `https://שם-המשתמש.github.io/notam-map/`
- נכנסים אליה — המפה באוויר! 🎉

### שלב 5 — בדיקת העדכון האוטומטי
במאגר: לשונית **Actions** → אם מופיע כפתור אישור ("I understand… enable them") לוחצים עליו → בצד בוחרים **עדכון נוטמים יומי** → **Run workflow → Run workflow**.
- תוך כדקה תראו ריצה עם ✅ ירוק — סימן שהמשיכה מרש"ת עבדה והנתונים התעדכנו
- אם מופיע ❌ אדום — לוחצים על הריצה ורואים את השגיאה (ראו "פתרון תקלות" למטה)
- מכאן והלאה זה רץ לבד כל בוקר — לא צריך לגעת יותר

### שלב 6 — הטמעה באתר Wix (שורה אחת!)
בעורך Wix: **Add → Embed Code → Embed HTML → Enter Code** ומדביקים רק את זה:

```html
<iframe src="https://שם-המשתמש.github.io/notam-map/"
        style="width:100%;height:100%;border:none" loading="lazy"></iframe>
```

(מחליפים את `שם-המשתמש` בשם האמיתי מהכתובת של שלב 4.)
מותחים את התיבה על כל הדף → **Publish**. מעכשיו האתר תמיד מציג את הגרסה העדכנית — בלי להדביק קוד מחדש לעולם.

## פתרון תקלות

**הריצה ב-Actions נכשלת עם שגיאת רשת / "הרשימה לא נטענה"**
כנראה חומת האש של רש"ת חוסמת את שרתי GitHub. פתרון: מריצים את `updater.py` ממחשב רגיל בארץ (פייתון מותקן → `python updater.py`) ומעלים את `notam-data.json` שנוצר למאגר (Upload files → Commit). אפשר לתזמן את זה ב-Windows Task Scheduler — והמפה עדיין מתעדכנת אוטומטית לכל הגולשים.

**המפה עולה אבל בלי מפת לוויין**
זה קורה רק בתצוגות מוטמעות מסוימות; בכתובת GitHub Pages הישירה הלוויין עובד תמיד.

**רוצים לעדכן ידנית עכשיו**
Actions → עדכון נוטמים יומי → Run workflow. תוך דקה הכל טרי.

**המקור המחייב לאזורים אסורים, מוגבלים ומסוכנים הוא פמ"ת פנים ארצי פרק א-17, בעדכון האחרון שפורסם.** כרגע: עדכון 1/26 מ-6 באוגוסט 2026 (`data/pmt-zones.json`, שדה `edition`). גם א-11 (תוכנית טיסה וטופס סגירה אווירית) וב-09 (כטב"מים) הם בעדכון 1/26, והעתקים שלהם שמורים ב-`data/source/` כבסיס להשוואה.

| שלב | מי מבצע | מתי |
|---|---|---|
| בדיקה אם פורסם עדכון חדש לא-17, ב-09 וא-11 + הורדת הקובץ מאתר רת"א | `.github/workflows/a17-quarterly.yml` (`scripts/a17_check.py`) | ה-1 בינואר/אפריל/יולי/אוקטובר |
| עדכון `data/pmt-zones.json` לפי הקובץ החדש, והגשה כ-Pull Request לאישור | Claude, בסשן שנפתח בעקבות ההתראה | אחרי ההתראה |
| התראה אם ההורדה נכשלה או אם הבדיקה לא רצה | Issue ב-GitHub (GitHub שולח מייל) + התראת דחיפה מריצה מתוזמנת של Claude | ה-1 וה-3 באותם חודשים |

- הקובץ שהורד נשמר ב-`data/source/<מסמך>-<מספר>-<שנה>.pdf` (בצירוף `.txt` לצורכי השוואה).
- אם הורדה אוטומטית נכשלת (למשל חסימה של האתר לשרתי GitHub): מעלים את הקובץ העדכני ל-`data/source/` (Add file → Upload files) או שולחים ל-Claude. כתובת ההורדה של א-11 טרם אומתה: כשלון בהורדה שלו נרשם ביומן ולא פותח Issue.
- הרצה ידנית של הבדיקה: **Actions → בדיקת עדכון פמ"ת א-17 (רבעוני) → Run workflow**.
- מייל ישיר מהבדיקה (בנוסף ל-Issue) אפשרי אם מגדירים ב-Settings → Secrets: `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_TO`.

### שכבת "מנחתים חקלאיים"
`data/agri-airstrips.json`: עשרה מנחתי ריסוס עם נ"צ ARP, המפעיל (כימניר / תלם) ופרטי הקשר של משרדי המבצעים, כפי שבטבלה בפמ"ת שסופקה על ידי הארגון (צילום מסך; הפרק ומספר העדכון אינם מצוינים בצילום). לעדכון: עורכים את הקובץ. הרשימה המלאה והמעודכנת מתקבלת במשרד מודיעין טיס.

## בקשת סגירה אווירית (נספח ג׳ לפמ״ת א-11) — `request.html`

לשונית "בקשת סגירה אווירית" בראש המפה מובילה לדף `request.html`. מזינים נקודה (לחיצה על המפה / הקלדה / חיפוש), רדיוס (ברירת מחדל 100 מ׳), גובה, תאריכים ושעות, מהות, כלי טיס, קשר עין ושם אתר (מתמלא לבד). לחיצה אחת מריצה את כל הבדיקות ומפיקה:
- טופס נספח ג׳ מלא (17 שדות) — מוכן להדפסה/שמירה כ-PDF;
- תמונת מפה על תצלום אוויר (Esri) עם עיגול ירוק (הרדיוס), כתום (עד פי 2), אזורי איסור בא-17 באדום, ומכשולים ממוספרים;
- דף בדיקות: מה נבדק ומה נמצא, יום/לילה, ימי עבודה, מגבלות המקורות;
- קובץ KML (Google Earth), וטקסט מייל לנוטאם (`notamoffice@iaa.gov.il`, `nofm@iaa.gov.il`; הקבצים מצרפים ידנית).

**מה נבדק (הכול אוטומטי):** אזורי א-17 (LLP/LLR/LLD/LLU/OBS) ושמורות/גנים של רט״ג (`data/pmt-zones.json`, `data/inpa-zones.json`); מנחתים חקלאיים (`data/agri-airstrips.json`); נוטמים בתוקף (`notam-data.json`); סביבה מ-OpenStreetMap דרך Overpass — מכשולים, קווי חשמל, כבישים, אזורים צבאיים, שדות תעופה ומנחתים, גבולות מדינה, שמות מקומות — בדפדפן עצמו.

**שער "מוכן לשליחה":** כל בדיקה שלא רצה או נכשלה (רשת, נתונים ישנים, אין רקע למפה, בדיקה עצמית) מסמנת את הבקשה "אינה מוכנה לשליחה" וחוסמת הדפסה/הורדה/מייל. בכל טעינה רצה בדיקה עצמית על נתוני אמת (נקודת הירקון) מול ערכים שחושבו בנפרד (`tests/expected.json`).

**פרטי אנשים:** שם וטלפון של המבקש ואנשי הקשר נשמרים בדפדפן בלבד (`localStorage`) ולא במאגר. במאגר רק פרטי הארגון (`data/request-config.json`).

**הגדרות שאפשר לערוך** ב-`data/request-config.json`: שם הארגון, מס׳ רישום, סימוני אזהרה, מהויות, כלי טיס, כתובות נמענים, ורף ה"קרבה" (`thresholds`).

**בדיקות:** `node --test tests/` (יחידה) ו-`node tests/e2e.mjs` (דפדפן מלא; דורש `playwright`). ב-GitHub: Actions → "בדיקות" (כולל הרצה חיה מול Overpass/Nominatim/תצלום אוויר).
